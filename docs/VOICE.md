# Documentation style

Write for someone installing or contributing to the product for the first time.

- Explain behavior, prerequisites and limitations before implementation details.
- Address the reader as "you" and their system as "the installation" or "the deployment".
- Use synthetic examples, reserved domains and documentation addresses. Preserve legitimate
  product names such as Homepage and Home Assistant, and required third-party attribution.
- Do not include personal names, installation identifiers, internal task numbers, private
  source revisions, agent transcripts or operational chronology.
- Describe current contracts directly. Link to maintained documentation and tests.
- Preserve API, schema and command literals unless a reviewed compatibility change requires
  otherwise. Distinguish implemented source, automated tests and live acceptance.
